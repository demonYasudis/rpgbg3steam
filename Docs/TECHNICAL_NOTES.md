## WP-01 — модель гексагональной сетки

`Assets/Scripts/HexGrid/` содержит чистые C#-типы без Unity API:

- `HexCoordinates`: неизменяемые axial `(q, r)`, равенство/хеш, шесть направлений,
  расстояние с промежуточными `long`, чтобы исключить переполнение при вычитании координат.
  Некорректный индекс направления вызывает исключение; сосед за диапазоном int — OverflowException.
- `HexGrid`: по умолчанию 12×12, размеры задаются в конструкторе. Это axial-параллелограмм,
  а не offset-прямоугольник: `0 <= q < Width`, `0 <= r < Height`.
  Перечисление клеток детерминировано: сначала q, затем r.
- `HexCell`: координаты, Terrain (`Ground`, `HighGround`, `Pit`, `Blocked`), OccupantId.
  Типы местности пока только хранятся, правила проходимости появятся позже.

`TryGetCell` возвращает false/null вне карты, `GetCell` выбрасывает ArgumentOutOfRangeException.
`GetNeighbors` выдаёт только существующие клетки в порядке `+q, +q-r, -r, -q, -q+r, +r`;
для исходной координаты вне карты — пустой набор.
`TryOccupy` и `TryVacate` меняют занятость через модель. ID непустой и уникален в пределах
сетки, чужой ID не освобождает клетку. Отказ не меняет состояние. Это ещё не система движения:
атомарное перемещение и связь с UnitRuntimeState относятся к следующим этапам.

## WP-03 — пути и диапазон движения

- `HexCell.MovementCost`: положительное целое, по умолчанию 1. Стоимость платится за
  вход в клетку; начальная клетка стоит 0. Нулевые и отрицательные значения отклоняются.
- `HexPathfinder.FindReachable(grid, origin, budget)`: Dijkstra в чистом C#, без Unity API.
  `Ground` и `HighGround` проходимы; `Blocked`, `Pit` и занятые назначения непроходимы.
  Только занятая стартовая клетка разрешена: считается, что в ней стоит движущийся юнит.
  Проверка принадлежности/права управления этим юнитом относится к вызывающему коду.
- `HexMovementRange`: снимок минимальных стоимостей `Costs` и восстановление маршрута
  `GetPathTo(destination)`. Включает начало со стоимостью 0; путь содержит начало и конец.
  Недоступная цель возвращает пустой путь. `FindPath` — удобный вызов того же поиска.
  Снимок и возвращаемые пути доступны только для чтения.
- Неверное/непроходимое начало даёт пустой результат. Неверная/недоступная цель — пустой
  путь. `null` вместо модели и отрицательный бюджет — исключения. Нулевой бюджет даёт
  только допустимое начало. Суммы защищены от переполнения; цена выше `int.MaxValue`
  не представима и такой маршрут недоступен даже при максимальном бюджете.
- Равные стоимости разрешаются по порядку первого обнаружения и фиксированному порядку
  соседей. Нет случайности и зависимости от порядка обхода Dictionary.
  Линейный выбор следующей клетки даёт O(V²), достаточно для поля из 144 клеток.
- `HexMovementPreview` связывает событие `HexGridInteraction.SelectionChanged` с поиском.
  Временное начало — выбранная клетка, бюджет по умолчанию 4, задаётся в GameBootstrap.
  `HexGridView.SetReachableCells` отображает зелёную область; выбор и наведение имеют
  приоритет. Уход наведения восстанавливает зелёный цвет; смена выбора удаляет старую область.
  HUD показывает бюджет и количество доступных назначений без стартовой клетки.

Пример использования из C#:

```csharp
var range = HexPathfinder.FindReachable(grid, start, movementBudget);
if (range.Costs.TryGetValue(destination, out int cost))
{
    var path = range.GetPathTo(destination);
    // path[0] == start; реальное перемещение будет реализовано в WP-04.
}
```

## WP-04 — герои и перемещение игрока

- `UnitDefinition` хранит неизменяемые общие данные класса; четыре определения находятся
  в `HeroDefinitions`. `UnitRuntimeState` отдельно хранит ID экземпляра и текущую клетку.
- `UnitRuntimeState.TryMoveAlong` повторно проверяет весь маршрут, соседство шагов,
  проходимость, занятость и бюджет. Только после успешной проверки `HexGrid.TryMoveOccupant`
  атомарно переносит занятость, после чего позиция runtime-состояния меняется один раз.
- `PlayerUnitController` создаёт Warrior, Rogue, Ranger и Mage в четырёх валидных клетках,

  Перед фиксацией путь рассчитывается заново, поэтому устаревшая подсветка не разрешает ход.
- Логическое перемещение фиксируется перед анимацией и резервирует цель. На время линейной

  выравнивается по центру логической клетки. Сейчас это не расходует ход — очередь относится к WP-05.
- `UnitView` создаёт временные цветные круглые маркеры без импортируемых ассетов.

## WP-05 — очередь ходов и состояния действий

Реализация готова к проверке в Unity; статус `[~]` до запуска Unity/Play Mode и проверки HUD.

- `Combat/TurnManager.cs` — чистая C#-модель. Порядок по убыванию Initiative; равенство
  сохраняет порядок переданного списка. В WP-05 инициатива фиксированная, без d20:
  Rogue 4, Ranger 3, Warrior 2, Mage 1. Сервис случайности относится к WP-06.
- Состояния: AwaitTurn → SelectingAction → Moving/ResolvingAction → SelectingAction →
  TurnComplete. Переход к следующему герою выполняется контроллером в следующем Update,
  поэтому повторное завершение одного хода не пропускает героя.
- Очки движения восстанавливаются при начале хода. Можно пройти несколько маршрутов,
  пока хватает остатка; списывается стоимость входа в клетки. Невалидный маршрут ничего
  не расходует. Действие доступно один раз за ход, независимо от движения.
- Команды игрока проходят через TurnManager; чужой ход, повторное действие и команды
  во время анимации отклоняются. `UnitRuntimeState.TryMoveAlong` остаётся низкоуровневой
  операцией проверки/фиксации маршрута: новые игровые команды должны использовать TurnManager.
- Временная кнопка Wait расходует действие и показывает ResolvingAction 0,35 секунды.
  Это проверка цикла, а не атака. End turn позволяет отказаться от оставшихся ресурсов.
- PlayerUnitController восстанавливает подсветку после включения. При отключении во время
  движения маркер выравнивается с уже зафиксированной целью; потраченные ресурсы не возвращаются.
  Прерванное ожидание считается использованным действием. Анимации используют unscaledDeltaTime.
- TurnOrderUI создаётся из GameBootstrap. HUD занимает верхние 204 пикселя; клики в этой
  области не отправляются на поле. Сцена, сериализованные поля и зависимости не менялись.

### Проверки и запуск

`Tools > Guild Tactics > Validate Turns` запускает проверки модели. Проверяются стабильность
при равной/крайней инициативе, 100 переходов, одиночный неподвижный герой, пустой/повторный
список, чужие команды, взвешенное и составное движение, расход/сброс ресурсов и блокировки.

Batch entry point: `GuildTactics.Editor.TurnChecks.RunBatch`. Он запускает прежние проверки
и Play Mode сохранённой сцены, затем проверяет завершение анимаций, блокировки повторного
ввода, смену героя, наличие UI и восстановление после отключения контроллера.
Сначала сохраните сцену и закройте редактор данного проекта. Запуск из корня проекта:

```powershell
$unityExe = 'C:\Program Files\Unity\Hub\Editor\6000.2.8f1\Editor\Unity.exe'
$projectPath = (Get-Location).Path
& $unityExe -batchmode -projectPath $projectPath -executeMethod GuildTactics.Editor.TurnChecks.RunBatch -logFile "$projectPath\Logs\wp05-check.log"
```

Не добавлять `-quit` и `-nographics`: сценарий сам завершает процесс и проверяет рендер.
Для ручной проверки: Play; очередь видна, выбирается Rogue; движение расходует очки;
Wait доступен один раз; во время обеих анимаций клики и End turn заблокированы;
после четырёх End turn начинается раунд 2 с восстановленными ресурсами.
Проверить HUD в 1280×720 и 640×960: снимки камеры не включают IMGUI.
